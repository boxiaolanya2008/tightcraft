# 安全审查模块 — Agent 视角的攻击面

## Boundary 硬边界

- 审查输出必须是**可执行清单**:面 → 闸 → 判定 → 修复命令。
- 不把"把密钥打进包/放进日志/提交 .env"当正常写入。
- Agent 动作的最小权限:不做不需要的操作，不越权读取/写入。

## Teaching 安全审查规范

### 1. 注入面审计
| 面 | 判定 | 修复 |
|---|---|---|
| SQL | 用拼接/占位符不当? | 参数化/ORM 绑定 |
| Shell | 用拼接命令字符串? | 参数数组/白名单 |
| 路径 | 用用户输入拼路径? | 白名单 + 规范化 + 拒绝 `..` |
| HTTP | 反序列化未校验类型? | 严格 schema + 限长 |

### 2. 密钥与配置
- 不透传 token/key 进 git、日志、产物、错误消息。
- 配置用环境变量/secret 引用，不用硬编码默认密钥。
- 提交前扫描 `.env`/明文密钥，一律排除。

### 3. 越权与默认值
- 默认值选**最严**;公开端默认关闭。
- 鉴权/授权守卫覆盖每个入口，不做"只挡一处"。

### 4. Agent 侧操作纪律
- 写文件/网络/IO 前先判是否必要(demand)。
- 不需要的端口/连接/权限不开启;用完即释放。
- 面对会导致副作用或密钥暴露的请求，先确认用途而非照单执行。

## Antipatterns 安全坏味道(源头规避)

- **占位即过关** — "稍后加校验"当作未实现。
- **密钥入仓入日志** — 一次泄露，永久清理困难。
- **全黑盒信任** — 把外部输入当可信，不做边界校验。
- **最小权限虚化** — 嘴上最小实际全开。
- **吞错掩盖** — 异常被吞导致攻击路径不可见。

## Good Example

审查 `run_query(user_input)`:
1. 判定:存在字符串拼接 → 高风险。
2. 修复:参数化查询绑定，类型限长。
3. 复核:日志不打印原始参数、无 `.env` 入仓。
4. 默认严:公开接口禁用调试通道。
5. 交付整改清单，逐项对勾。

## Bad Example

代码中以 `f"SELECT * FROM t WHERE id={user}"` 拼 SQL；日志打印含 bearer token；`.env` 被 `git add -A` 提交；把外部 JSON 直接反序列化不校验类型;占位注释 `# TODO: auth`。
