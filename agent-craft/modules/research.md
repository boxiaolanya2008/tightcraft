# 检索溯源模块 — 采集不等于全信

## Boundary 硬边界

- 每个**断言必须带溯源**:来源、版本/时间、锚点定位，缺一即标注"未核验"。
- 一手源(官方文档/源码/原始数据)优先于二手转载。
- 链接、版本号、命令**必须真实**；占位符/异想 URL 视为无效。
- 获取主流版本信息用当前年份检索，不用历史快照当最新。

## Teaching 检索最优做法

### 1. 问题锚定
把"查一下 X"压成**可回答的具体问题**:限定实体、版本、平台。

### 2. 溯源分级

| 级别 | 例 | 采信 |
|---|---|---|
| 一手 | 官方文档 | 最高 |
| 二手权威 | 大厂博客/标准规范 | 中 |
| 社区/转载 | 论坛/未署名 | 需交叉核验 |

### 3. 交叉核验
- 命中的关键事实用 ≥2 独立源对证。
- 版本差异:检索时带年份；对不上的标注差异区间。
- 过时风险 API:锚定其 deprecation 与替代方案。

### 4. 可核验断言模板
`结论 [+ 来源(标题+URL) + 版本/日期 + 引用行/章节]`；拿不到锚点就写"最佳可得"而非冒充精确。

### 5. 反幻觉自检
- "应该有"/"我记得"→ 必须落地到链接或源码。
- 缺证时**显式声明缺失项**，不臆测填充。

## Antipatterns 检索坏味道(源头规避)

- **无源断言** — 引用"新版/文档说"不给链接版本。
- **二手当一手** — 转载覆盖官方差异。
- **过期不标** — 拿旧版本当现状。
- **占位链接** — `https://example.com/...` 当真实引用。
- **取buff生成** — 再包装后链路断裂，信息失真。

## Good Example

"得让我先查 Godot 4.2 的引擎导出" →
1. 一手源:官方 docs 导出页(URL·版本)。
2. 锚点:Export → Platform。
3. 断言:支持 Win/Linux/mac/Web/Android/iOS + 关键限制一句。
4. 附版本与引用 URL，标注无降级项。"据官方文档 Godot 4.2 …… "

## Bad Example

"目前主流引擎都支持一键导出" — 无版本无链接；引用某论坛三年前旧帖当现状；塞一条 `https://three.example` 假链接。
