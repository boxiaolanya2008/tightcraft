# 任务规划模块 — 契约化拆解与推进

## Boundary 硬边界

- 动工前先出**契约**:目标、交付物、边界、验收标准；中途不得静默新增/删改。
- 步骤粒度 = **可独立验证的最小单元**；每步一个明确出口(exit criterion)。
- 依赖必须先于被依赖者；无环。
- 规模判断:步骤 >7 或跨 >3 文件 → 必须拆成批次并设检查点。

## Teaching 规划最优做法

### 1. 逆向契约(从验收反推)
先定"做完长什么样、怎么证明"，再反推步骤。验证标准优先于执行顺序声明。

### 2. WBS 拆解
- 用 **动词短语** 命名每步(`load config`、`validate schema`)，表达产出而非状态。
- 每步自带:**输入契约、输出(可观察)、失败路径**三要素。
- 独立子任务压入并行；同资源冲突的串行。

### 3. 依赖拓扑
```
[T] 单张 DAG:步骤→前置。有环即错误;环 → 合并或裂解。
```
- 入口节点无入边;出口节点无出边。
- 变更波及:改任一步，重算其后继的契约命中。

### 4. 风险预判分级

| 级别 | 判定 | 处置 |
|---|---|---|
| 高(阻塞) | 未知 API/未明契约/外部依赖 | 先做 spike 探路再入主线 |
| 中(可降级) | 边界模糊但可实现 | 冻结一个保守契约，标明取舍 |
| 低(直接) | 清晰、无外部依赖 | 基线批次直接执行 |

### 5. 检查点节奏
每批结束做同步点:**契约命中?命名/错误策略一致?有无新依赖未报备?** 不达标当批修正，不积攒。

## Antipatterns 规划坏味道(源头规避)

- **目标即验收缺失** — 只写"实现模块"，不写"输入 X 得 Y、错误 Z 抛 E"。
- **步骤粒度失控** — 一步横跨数十行无出口，等于不拆。
- **忽略依赖环** — DAG 出现环却继续写，必然返工。
- **风险不预判** — 拿未知 API 直接开写，中段才撞墙。
- **检查点形同虚设** — 每批不做验证就往下走，漂移累积。
- **范围悄悄膨胀** —"顺手加个功能"未进契约即不算。

## Good Example

契约:迁移 `sync_users(rows)` 到批量入库。
1. `extract_contract` — 读旧函数签名/返回/异常，冻结(出口:契约快照)。
2. `spike_batch` — 以 500/批验证 API 上限(出口:压测输出)。
3. `reimplement` — 按契约重写，命中签名与错误策略(出口:静态自检)。
4. `port_tests` — 旧用例跑绿 + 新批边界(出口:全绿)。
5. `regression` — 全域回归，函数名/错误/返回零漂移(出口:回归日志)。

## Bad Example

"实现批量入库功能" —— 无验收、无依赖图、直接开写；写到第三步发现 API 有批次上限，往回倒退重写，未设检查点，命名从 `batch_insert` 漂到 `db_update`。
