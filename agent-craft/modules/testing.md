# 测试策略模块 — 让行为可证明

## Boundary 硬边界

- "核心路径必有测试"为下限:主 happy path + 关键错误路径。
- 测试**先写再用**——先红后绿，证明测试真的在测。
- 每个用例只验证一件事，断言有明确预期值。
- 不引入第二测试框架；用语言既有标准。

## Teaching 测试最优做法

### 1. 测试金字塔

| 层 | 覆盖 | 快慢 | 维护 |
|---|---|---|---|
| 单元 | 纯逻辑、无外部 I/O | 快 | 低 |
| 集成 | 模块间契约、DB/服务桩 | 中 | 中 |
| E2E | 用户可见主流程 | 慢 | 高 |

构建重心放在**单元层**；集成/E2E 只保关键链路。

### 2. 可测性判定(先问再写)
- 逻辑是否与 I/O 解耦?耦合 → 显式注入依赖。
- 纯函数是否可独立调用?否 → 抽取。
- 时间/随机/环境是否可注入?否 → 参数化。

### 3. 用例命名 = 行为句
`[动作]_给定[前提]_期望[结果]` → 一眼知意图。

### 4. 边界与负路径
- 空输入、超限、非法格式、外部异常 → 必须有归宿（或用例覆盖错误路径）。
- 每个 `if` 分支至少一条用例。

### 5. 断言质量
- 断言**行为**而非内部实现(freedom from truthy-only)。
- 用与期望相同单位的比较，避免魔法常量裸奔。

## Antipatterns 测试坏味道(源头规避)

- **过测实现细节** — 锁定内部字段名，重构即红。
- **只测 happy** — 冒烟也算覆盖，错误路径裸露。
- **断言无值** — `assert result`/`assert not raised`，等于没断言。
- **测试与偶发耦合** — 依赖网络/共享库/时间，结果不稳定。
- **为覆盖率凑数** — 有空分支/空断言填充比例。
- **测试一刀不分层** — 全堆 E2E，慢且脆。

## Good Example

函数:`apply_discount(price, rate)` 契约:price≥0、0<rate≤1、否则抛 `ValueError`。
1. happy:`apply_discount(100, 0.9) == 90`。
2. boundary:`apply_discount(0, 0.9) == 0`;`apply_discount(100, 1) == 100`。
3. error:`apply_discount(-1, 0.9)` 抛;`apply_discount(100, 1.2)` 抛。
先写红 → 实现 → 全绿。

## Bad Example

一个不含 import 的 `test_smoke()` 直接 `pass`；覆盖率报表 95% 实为空断言；用例连数据库、随时超时，CI 间歇红。
