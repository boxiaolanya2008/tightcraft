# 记忆模块 — 会话内内容锁存 + 指纹失效

## Boundary 硬边界

- 同一文件的**内容**,在一轮对话生命周期内**最多完整读取一次**。
- 读取 token 只在**首次读 与 内容变化时**发生;其余引用一律走记忆。
- 会话记忆表占用受 `THINK_TOKEN_CAP` / `OUTPUT_TOKEN_CAP` 约束,摘要化存储。

## 核心机制:锁存 + 指纹失效

会话内维护一张**内容锁存表**(不在输出中展示,仅供代理念理使用):

| 路径 | 内容摘要 | 指纹(哈希/签名) | 最后访问 |
|---|---|---|---|
| config/env.js | <摘要> | a3f9… | now |

工作流:

1. **首次读取(Latch on)** — 读文件,抽取内容,计算**指纹**,连同摘要存入锁存表。
2. **后续引用(Reuse)** — 先查表。命中且指纹匹配 → 直接用记忆,不重新读、不增输入 token。
3. **失效检查(Invalidate)** — 用到某文件前,重算其指纹。与表中一致 → 记忆有效;不一致 → 重读并刷新表。

## Teaching 指纹与失效判定

- **指纹** = 稳定标识内容版本:优先取内容签名/哈希;不可得时取「修改时间+长度」组合。
- **失效判定**:指纹变化即失效。未变 → 铁定复用;变了 → 必须重读,不得沿用旧记忆。
- **刷新** 后清空该条旧摘要与旧指纹,只留最新。

## 摘要化存储(控制 token)

- 锁存表只存**摘要**,不存全文,降低记忆占用。
- 摘要要足够支撑引用(变量名、导出、关键常量),不承载全部实现细节。
- 需要完整细节时才允许一次定向重读。

## Antipatterns 记忆坏味道

- **每次都全文重读** — 相同文件反复读,逐次烧 token。
- **无视修改** — 文件已变仍用旧记忆作答,信息失真。
- **无摘要** — 把整份文件压进上下文,记忆区爆炸。
- **无路径绑定** — 记忆不关联来源路径,无法判断去哪验证失效。
- **跨会话误当已锁存** — 新会话不自动继承,须重新锁存(本模块仅会话内)。

## Good / Bad Example

- Good:读取 `config.js` → 锁存 a3f9。10 步后再引用,指纹未变 → 直接记忆,零重读。
- Bad:每步都读 `config.js` 全文;或文件改了仍引用 {内存值} 旧态,输出过期配置。
