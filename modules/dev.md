# 开发过程一致性模块 — 防漂移(anti-drift)编码纪律

## Boundary 硬边界

- 下笔前,先把**契约冻结**:函数签名、输入契约、边界策略、错误策略、依赖集,一次性确定,中途不得新增/变动。
- 生成按「最小可验证单元」分块,每块结束做同步点自检,不允许连续写大段后一次性收尾。
- 任何一块偏离已定契约或 Skill → 立即修正,不得"先记着最后再改"。

## 根因:AI 编码漂移

长流程编码的系统性失败模式:

1. **契约遗忘** — 开头定的边界/错误约定,写到中场忘光。
2. **样例污染** — 复制前一段的风格,把临时命名/硬编码带入后续。
3. **规则松动** — 开头严守 Skill,尾段"随手能跑就行"。
4. **一致性破碎** — 前置校验只在第一处,后面不再校验。

目标:让模型像「持有状态机」那样编码——每一步都对现状(state)和契约(constract),而非重启推理。

## Teaching 防漂移三支柱

### 1. 契约冻结(Contract Locking)
生成第一行代码前,先在心里(或注释草稿中)固定:

- 本函数/模块的**输入输出签名**与**返回契约**。
- 哪些输入**必须校验**,哪些可信任;错误走**抛/聚拢/重试**哪条策略。
- 允许的依赖集与命名风格;禁止项(list)。

契约一旦锁定,**后续所有代码必须命中它**,不得中途发明新规则或偷懒简化。

### 2. 节奏化自查(Beat Checkpoints)
把长实现拆成可独立验证的「节拍」。每完成一拍,停一下过同步点:

- 本拍是否命中冻结契约?(签名/边界/错误)
- 本拍是否符合 Skill(coding.md)?
- 本拍有没有把临时命名/硬编码泄漏给下一拍?

不达标 → 当拍即修,不带病前行。所有待修正项在当拍消化,不积攒。

### 3. 增量新规检测(Incremental Drift Net)
每新增一块代码,主动对照「已生成的上一块」:

- 命名/错误处理/防御风格是否一致?不一致即为 drift。
- 是否悄悄改变了初始的返回值结构或失败语义?是则回退。
- 是否新增了未报备的依赖或外部作用?是则移除或明确说明。

### 4. 收尾回归(Regression Gate)
全部完成后,做一次全域一致性回归,再交付:

- 全链路:最早调入口到最末返回,裁剪一遍,确认每处边界与错误都有归宿。
- 全契约:所有函数签名、命中冻结契约,无中途变形。
- 全 Skill:过一遍 coding.md 的去AI味清单与审查清单。
- 全一致:无风格漂移、无临时命名残留、无重复防御、无臆测代码。

任一不过 → 回到对应节拍修正,重新回归,而非修补补丁。

## 心理状态机(编码时自问)

| 此刻阶段 | 唯一自问 |
|---|---|
| 下笔前 | 契约冻结了吗? |
| 每写完一拍 | 本拍命中契约与 Skill 吗? |
| 引入新代码 | 与上一块一致且未改契约吗? |
| 收尾前 | 全域回归过了吗? |

## Antipatterns 漂移症状(即时识别)

- 开头有校验,写了 30 行后输入直接裸用 → drift。
- 早期 `fetch_user`,中段变成 `getData` → 命名漂移。
- 契约 `raise ValueError`,后段改成 `return None` → 错误策略漂移。
- 接口函数返 JSON,末尾函数返对象 → 结构漂移。
- 写到后段开始「嗯这里就随便处理下」 → 规则松动,立即停下回正。

## Good Example

契约:`load_balance(users, cap)` 校验 cap≥1、返回 dict、非法输入 raise。
一拍一拍实现,每拍核对签名才继续;结尾回归发现某分支未校验 = 命中契约,补齐后交付。

## Bad Example

开头定义契约 `raise ValueError`,`...` 写 80 行后新增分支直接 `return None` 且未校验输入;命名从 `user_id` 漂到 `x`;结尾没回归,直接把"能跑"当完成。
