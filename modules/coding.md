# 编码规范模块 — 健壮、安全、无坏味道

## Boundary 硬边界

- 目标 token 预算同上;仅在用户要求完整实现时放宽。
- 不产出仅"演示能跑"的样板:每个依赖必须被证明必要。
- 公共函数必须可被独立调用方理解:显式契约、明确错误。

## Teaching 规范

### 1. 语言原生 / 标准库优先
- 不引入第三方库(工具库、UI 库)除非不可替代。标准库/原生 API 能解决就不引依赖 → 最小依赖树。
- 引入前问:没有它是否就写不出来?

### 2. 安全默认值(全语言通用)
- 不信任任何外部输入;所有入口做校验。
- 不打印或提交密钥凭证;密钥不进仓库、不落日志。
- 按最小权限设计:只暴露需要暴露的。

### 3. 防御性编程(语言无关)
- 强边界:空值、超限、网络异常、竞态,一律显式兜底。
- 错误向上层抛或聚拢统一处理,不在函数内部撒满分支。
- 每一条 code path 有明确结局,不隐形失败。

### 4. 高内聚低耦合
- 单一职责:一个函数只做它那一层的事。
- 可扩展演进,而非堆补丁。

### 5. 类型与命名
- 显式类型/强推导;公共接口定义清晰契约。
- 命名表意图:`max_retries` 而非 `n`;动词谓语的函数名。

### 6. 并发与状态(多语言)
- 共享可变状态最小化;锁定或不可变二选一。
- 事务/一致性:明确读-改-写是否为原子。
- 并发场景标注线程/协程安全上下文。

### 7. 错误处理分类
| 错误类型 | 处理 |
|---|---|
| 可恢复(重试/降级) | 捕获,按策略恢复或重试 |
| 不可恢复(契约违反) | 快速失败,抛出明确错误 |
| 外来异常 | 解包/归类,保留根因链 |
- 禁止:吞错合并、空 catch、把定位信息丢失。

## Antipatterns 编码坏味道(源头规避)

- **依赖堆砌** — 无脑引 UI/工具库代替自研。
- **吞错合并** — 所有异常并成一种,丢失定位。
- **魔法数字/硬编码** — 应命名的裸露值。
- **过度注释** — 装饰分隔符、解释显而易见逻辑的废话注释。
- **复制粘贴代码** — 应抽取未抽取。
- **能跑就行** — 无校验、无类型、无错误处理的最小版。
- **过早优化** — 先做对,用数据驱动再优化。
- **全局裸状态** — 隐式共享可变全局,难测难排。

## 语言无关审查清单(交付前自检)

1. 每个入口校验了吗?没有路径能拿到未初始化/空值。
2. 每个错误有明确去处吗?没有静默吞掉。
3. 每行是必需的、能跑，且无重复吗?
4. 依赖能再少一个吗?
5. 命名表意、契约自明、可被新维护者直接读懂吗?

## 去 AI 味代码(De-AI'd Code) — 强制遵守

以下范本与坏味对照为**硬性标准**:提交代码前,必须去除如下「AI 招牌动作」,否则视为未完成。

### 1. 命名去 AI 味
- 禁 `temp`/`data`/`result`/`thing`/`item`/`handleSomething` 这类空洞命名。
- 用语义化真名:`user_id`、`next_retry_delay_ms`、`max_connections`。
- AI 标志:`userInput`(腔)、`inputData`(空)、`myFunction`(自指)。

### 2. 结构去 AI 味
- 禁「大段落 + 高内聚」伪装的巨型单函数;按职责拆函数。
- 禁不必要的抽象:`ConfigManager` 包一个 dict;`Util` 满天飞。
- 禁过度封装导致的一层套一层,能直写就别绕。

### 3. 注释去 AI 味
- 禁装饰分隔符(`// ====`)、禁解释显而易见逻辑的废话注释。
- 禁「数据流图+情绪词」式长段注释。
- 注释只留:为何这么做(非显而易见)、数学/时序原理、对外契约。

### 4. 逻辑去 AI 味
- 禁「担心过度」的三重防御(重复校验同一输入)。
- 禁「面面俱到」的空分支/空实现体,留给真实边界。
- 禁给假设加一堆"也许会……所以顺便"的臆测代码。

### 5. AI 味代码 → 去 AI 味代码(对照)

| 辣 AI 味 | 去 AI 味 |
|---|---|
| `// 获取数据\nfunction fetchData() { ... }` | `async function loadRecentOrders(userId) { ... }` |
| `// 处理逻辑\n// 要遍历所有条目找出合适的` | `const active = orders.filter(o => o.status === 'active')` |
| `let temp = 0;\n// 循环累计求和` | `const total = items.reduce((s, i) => s + i.qty, 0)` |
| 5 行分隔注释声明段 | 零注释,命名自明 |

### 6. 提交前「去 AI 味」清单

1. 有没有空洞变量名/自指名?改真名。
2. 有没有装饰注释或解释废话的注释?删。
3. 有没有可读性因「过度防御/过度抽象」而下降?简。
4. 去掉注释后,代码是否仍自明?是 → 注释可删。
5. 若让高级工程师匿名评审,能否一眼认出"这是 AI 写的"?能 → 重构。

## Good Example

```python
def serialize_user(user):
    return {"id": user.id, "email": user.email.lower()}
```

## Bad Example

```python
# ============================================
# 这个函数用来把用户数据序列化一下
# 注意:email一定要全都转成小写,因为……(3行理由)
# ============================================
def processUserData(inputData):   # 空洞命名 + 首参数语义弱
    temp = {}
    temp['ID'] = inputData.user.id
    temp['EMAIL'] = inputData.email.lower()
    return temp
```
